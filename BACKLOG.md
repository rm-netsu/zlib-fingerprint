# Отложенные проверки и улучшения zlib-fingerprint

Ниже — намеренно **отложенные**, а не выполненные задачи. Они не блокируют
текущую интеграцию обнаруженных классов в реестр поиска.

## P1 — подтверждение классов при других сценариях API

- [ ] Прогнать все версии с `Z_SYNC_FLUSH`, `Z_FULL_FLUSH`, `Z_BLOCK` и
  `Z_PARTIAL_FLUSH` в разных точках входного потока; сохранить первые
  отличающиеся байты и исходные параметры.
- [ ] Проверить разбиение входа на порции 1, 2, 64, 512, 16 384 и 65 535 байт
  и выходные буферы 1–65 536 байт; особенно границу 1.2.9/1.2.10.
- [ ] Проверить `deflateParams`, смену уровня и стратегии посреди потока,
  `deflateReset`, `deflateCopy`, пользовательский `memLevel` и `windowBits`.
- [ ] Протестировать `deflateSetDictionary` с одинаковыми словарями, короткими
  и длинными словарями, включая особенности заголовка FDICT.
- [ ] Расширить дифференциальную матрицу до `--depth full`, увеличить данные
  до нескольких МиБ и добавить специально подобранные границы хеш-таблиц,
  `MIN_MATCH`, `MAX_MATCH` и pending buffer.

## P1 — корректность вывода о версиях

- [ ] Найти успешное побайтовое отличие 1.2.2 от 1.2.3 при общих допустимых
  параметрах **или** документировать, что разделение обусловлено только
  поддержкой `Z_FIXED` и иных функций API.
- [ ] Перепроверить 1.3.2 относительно 1.3.1 на потоковом API; до этого
  не считать 1.3.2 доказанно покрытой встроенным Zig-движком.
- [ ] Верифицировать каждую группу A–D под `avail_out` ограничениями для
  *всех* входящих версий, а не только соседних представителей.
- [ ] Дифференцировать неопределённое поведение/падения старых версий
  (`Z_HUFFMAN_ONLY`, `Z_RLE`, малые буферы) от легального результата;
  запускать нестабильные кейсы под ASan/UBSan.

## P2 — расширение покрытия

- [ ] Исследовать экспериментальные 0.x выпуски (до 1.0.1), различия
  заголовка RFC 1950 и совместимость API обёртки.
- [ ] Повторить тесты на x86-64 и ARM64, с разными опциями сборки,
  включая `FASTEST`, `UNALIGNED_OK`, `-O0/-O2/-O3`.
- [x] Убрать зависимость классов A–D от внешних исполняемых файлов:
  оригинальные C-ядра статически интегрированы в Zig-приложение.
- [x] Перевести класс D (1.2.1–1.2.2) на общий Zig-движок 1.2.3 с учётом
  ограничений допустимых стратегий. Дифференциальная сверка с оригинальной
  1.2.2: 3168 проб, 2592 совпавших успешных потока (один Z_FINISH).
- [x] Нативно перенести различающиеся пути ядра C (1.1.0–1.2.0): выключенная
  эвристика TRUNCATE_BLOCK, легаси-формула FLEVEL, старая fill_window,
  отказ от windowBits 8. Сверка: 43 619 сравнений с C-оракулом и всеми 16
  официальными бинарниками класса — 0 расхождений
  (`scripts/diff_native_legacy.py`, 2026-11-25).
- [x] Нативно перенести различающиеся пути ядер B и A (1.0.x): раннее
  отсечение блока в _tr_tally (класс B), разбиение stored-блоков 0xffff/
  MAX_DIST без ограничения pending-буфера (класс A), windowBits 8
  у 1.0.x (уровень 0 — побайтово, включая детерминированный «теряющий
  данные» поток; уровень >= 1 — UB оригинала, исключено из поиска);
  убрать C из production build после независимой побайтовой сверки
  (исполняемый файл zlib-fingerprint больше не компилирует алгоритмический
  C-код zlib; оригинальные ядра остаются в dev-инструменте zlegacy как
  дифференциальные оракулы).
- [ ] Устранить либо безопасно эмулировать известные аварийные пути
  исторического C при level=0, необычных стратегиях и малом memLevel
  (частично: недетерминированные/UB-пути задокументированы и исключены
  из поиска; остаётся прогнать оригиналы под ASan/UBSan и зафиксировать
  поведение).
- [ ] Построить автоматическую регрессию: каждое найденное отличие
  сохраняется минимальным fixture и проверяется CI.

Текущие воспроизводимые результаты: [EQUIVALENCE.md](EQUIVALENCE.md),
`equivalence-results.json`, `boundary-results.json`.
