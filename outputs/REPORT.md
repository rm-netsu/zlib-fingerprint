# Отчёт: интеграция исторических выпусков Zopfli (1.0.0–1.0.3) в zlib-fingerprint

Дата: 2026-10-29. Язык: Zig 0.16.0. Платформа проверок: linux x86_64
(сборка и запуск). Кросс-компиляция проверена для aarch64-linux-gnu,
x86_64-windows-gnu, x86_64-macos (только сборка; запуск на этих платформах
не выполнялся).

Выполнены этапы 3–7 плана работ поверх завершённых этапов 1–2
(базовая линия — `zlib-fingerprint-zopfli-1.0.3-native-complete.tar.xz`,
SHA-256 `0d9470426923aa2e8fef6a8f92d1fd3fb0c33f85e916f0ef3690eff72ce3a7bc`).

## Наблюдаемые классы эквивалентности

Побайтовая матрица (`scripts/version_matrix.py`): 38 входов × 356 комбинаций
(4 эталонных CLI + 4 нативных варианта на каждую), корпус включает пустой и
короткие вводы, повторы, периодические последовательности, повторное
использование словаря, текст, JSON-подобные данные, случайные байты с
фиксированными seed, смешанные сжимаемые/несжимаемые области, границы окна
32 КиБ, границы master-блоков 999999/1000000/1000001 и 20 000 001 байт,
а также входы, направленно затрагивающие обнаруженные различия энкодера
дерева. Каждый поток проверен обратной распаковкой; записаны версия,
параметры, идентификатор входа, статус, размер и SHA-256
(`version-matrix.json`).

| Группа | Выпуски | Совпадение | Первое различающее воспроизведение |
|---|---|---|---|
| G1 | 1.0.0 | — | — |
| G2 | 1.0.1 | совпадает с G1 на 38/89 комбинаций | G1≠G2: `periodic-4096`, 1 итерация |
| G3 | 1.0.2 + 1.0.3 | побайтово идентичны на 89/89 | от G1/G2 отличаются на 89/89, минимальное — `empty`, 1 итерация |

Объединение групп подкреплено анализом исходников (diff тегов и история
коммитов): 1.0.2→1.0.3 меняет только cast в `malloc` (без поведенческих
эффектов); 1.0.1→1.0.2 — FLEVEL 0→3 (`05e3efc`), master-блок 20 МБ→1 МБ
(`fdb3745`), try-both `OptimizeHuffmanForRle` (`e0e937e`), auto-типы блоков,
второй проход разбиения, исправление пустого ввода; 1.0.0→1.0.1 — новый
8-стратегийный энкодер дерева (`b87006b`, `150827f`) и обязательная
RLE-оптимизация гистограмм. Матрица подтверждает: на проверенном корпусе
G3 неразличима, G1 и G2 различимы.

## Изменения архитектуры

- Новый модуль `src/zopfli/release.zig`: явный вариант `ZopfliRelease`
  (без изменяемого глобального переключателя), канонические опции
  с полем `variant`, метаданные выпусков (заголовок, master-блок, поведение
  на пустом вводе).
- `deflate_tree_encode.zig`: легаси-энкодер дерева 1.0.0
  (`addDynamicTreeLegacy`, фиксированная RLE-стратегия, байтовая учётная
  особенность `CalculateTreeSize` воспроизведена) + диспетчер по варианту.
- `deflate_dynamic.zig`: три модели динамических длин — 1.0.0 без RLE,
  1.0.1 всегда-RLE, 1.0.2+ try-both.
- `deflate_block_size.zig` / `deflate_cost.zig` / `blocksplitter.zig`:
  вариантные модели стоимости (легаси — dynamic-only, новые — auto-type).
- `deflate_driver.zig`: легаси-оркестрация `DeflateSplittingFirst`
  с доновыбором fixed-дерева для малых блоков; master-блок 20 МБ / 1 МБ;
  пустой ввод: легаси ничего не выдаёт (как upstream-библиотека), нативный
  API отвергает его ошибкой (как upstream-CLI).
- `squeeze_forward.zig`: легаси-выражение отсечения
  (`costs[j+k] - costs[j] <= mincost`) для 1.0.0/1.0.1.
- `container.zig`: заголовок по варианту (`78 01` / `78 da`).
- `native.zig::compress(allocator, input, iterations, variant)`.
- `profiles.zig` / `hints.zig` / `fingerprint.zig`: профили четырёх
  выпусков, предсказание заголовка по выпуску, свёртка 1.0.2 в
  представителя 1.0.3 с отчётом группы `zopfli 1.0.2-1.0.3`, примечание
  о неоднозначности stored-потоков (stored-блоки байт-в-байт совпадают у
  zlib и всех выпусков Zopfli).
- `verbose.zig`: verbose-вывод ядра без C-глобала `stderr`
  (устранена ошибка кросс-сборки Windows).
- `zzopfli`: `zzopfli <итерации> [1.0.0|1.0.1|1.0.2|1.0.3]`.

## Команды воспроизведения

```sh
# окружение: Zig 0.16.0, gcc, python3, сетевой доступ к github.com
tar -xJf zlib-fingerprint-zopfli-releases-complete.tar.xz
cd zlib-fingerprint-zopfli-releases-complete
zig build --release=fast && zig build test
make -C binaries/vendor/zopfli-zopfli-1.0.3 zopfli

# эталонные CLI выпусков (пример для 1.0.2; пути настраиваются --references)
tar -xzf zopfli-1.0.2.tar.gz && cd zopfli-zopfli-1.0.2 && make zopfli && cd ../..
export ZOPFLI_REFS=<каталог с built-1.0.0/built-1.0.1/built-1.0.2>

python3 scripts/diff_zopfli_native.py      # 356/356
python3 scripts/diff_katajainen.py         # 4042/4042
python3 scripts/version_matrix.py          # полная матрица (или --quick / --from/--to)
python3 scripts/fingerprint_release_check.py
python3 scripts/zopfli_ordering_bench.py
```

Матрица умеет дробиться на порции (`--from/--to`, `--output`) и собираться
`scripts/merge_matrix.py` — так отчёт воспроизводим на машинах с малым
объёмом памяти. При отсутствии эталонных CLI 1.0.0–1.0.2
`diff_zopfli_native.py` проверяет контейнеры и доступные пары, явно сообщая
число пропущенных комбинаций.

## Оставшиеся ограничения

- Фактический запуск на ARM64/macOS/Windows не выполнялся (только
  кросс-компиляция); требуется среда соответствующей платформы.
- Матрица покрыта итерациями {1, 2, 3, 5, 10, 15, 50} (+ 1..30 в итерационном
  зонде) и корпусом ≤ 20 МБ; итерации вне набора и входы за пределами корпуса
  матрицей не охвачены — это наблюдаемая, а не универсальная эквивалентность.
- zlib-обёртки внешних альтернативных компрессоров (zlib-ng, libdeflate,
  miniz, advdef) не пересобирались: в переданном архиве отсутствует
  `binaries/zlib_ng_wrapper.c`, а загрузка fossils с zlib.net закрыта
  Cloudflare-челленджем; регрессия zlib выполнена по 30 официальным
  обёрткам zlib 1.0.1–1.3.2, собранным из тегов madler/zlib и fossils
  (1.1.4–1.2.2 — из git-тегов). Это не влияет на задачу Zopfli.
- Поддержка потокового API zlib (flush-режимы, словари, порции) остаётся
  в бэклоге — вне рамок этапов 3–7.
